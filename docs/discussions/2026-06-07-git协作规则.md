## ❓ 5 个核心问题 (全部待定)

### Q1 · 分支策略

**问题:** 每个子 agent 用独立分支?还是独立 worktree?worktree 之间怎么对应分支?

**候选:**
- **A. 一 agent 一分支** → `backend-dev`, `frontend-dev`, `ai-dev`
- **B. 一 agent 一任务一分支** → `feature/S0-18-auth`, `feature/S0-19-project`
- **C. 主线 + worktree** → 都基于 `main`,worktree 内部 commit

**待定** ❓

---

### Q2 · commit 规范

**问题:** 谁先 commit?消息怎么写 (中文/英文/Conventional Commits)?

**候选:**
- **A. Conventional 英文** → `feat(auth): implement login endpoint`
- **B. Conventional 中文** → `feat(auth): 实现登录端点`
- **C. 任务 ID 前缀** → `[S0-18] auth login endpoint`
- **D. 子 agent 自由** → 只要写清楚就行

**关联问题:** commit 是否要带 `Co-Authored-By: Claude` 或 agent 标识?

**待定** ❓

---

### Q3 · 合并节奏

**问题:** 子 agent 完工立即合主控?还是攒一批合?

**候选:**
- **A. 完一个合一个** → 简单,但合并频繁
- **B. Sprint 结束合** → 批量合,但中间互相看不到
- **C. 主链合并 + 长开 PR** → 用 PR 走 review
- **D. 主控仲裁后合** → 主控 review 才合

**关联问题:** 是否需要 CI 跑契约 lint?lint 不过禁止合?

**待定** ❓

---

### Q4 · 冲突解决

**问题:** 两个 agent 改同一文件怎么办?

**候选:**
- **A. 主控仲裁** → 自动 detect 冲突,主控判谁对
- **B. 后到的让先到** → 时间戳优先
- **C. 强制隔离边界** → 在 CLAUDE.md 写死"你只能改 backend/src/modules/auth/"
- **D. 三方合并工具** → 用 git merge 工具自动

**特别敏感:** `contracts/` 谁改谁错 (除非主控显式批准)。

**待定** ❓

---

### Q5 · 契约保护 (`contracts/` 是禁区)

**问题:** 是否需要 pre-commit hook 阻止子 agent 改 `contracts/`?

**候选:**
- **A. pre-commit hook** → 子 agent 改 contracts/ 直接拒 commit
- **B. CI 检测** → 改了报警,主控决定
- **C. CLAUDE.md 约定** → 仅靠子 agent 自觉
- **D. 文件权限** → contracts/ 设只读 (操作系统级)

**待定** ❓

## ✅ 5 核心 + 3 延伸问题拍板结果 (2026-06-07)

| Q | 问题 | 最终决策 |
|---|------|---------|
| **Q1** | 分支策略 | **一任务一分支 + worktree** (`feature/S0-XX`) |
| **Q2** | commit 规范 | **任务 ID 前缀 + Conventional 中文** (`[S0-18] feat(auth): 实现登录`) |
| **Q3** | 合并节奏 | **两档制** (普通 CI 自动合, 敏感主控人审) |
| **Q4** | 冲突解决 | **3 层防御** (边界约束 → 自动合并 → 主控仲裁) |
| **Q5** | 契约保护 | **pre-commit hook + CI 双保险** |
| **E1** | push 远程 | ✅ **必须 push** |
| **E2** | tag 规则 | **Sprint→版本号** (v0.1.0 → v0.2.0 → v1.0.0) |
| **E3** | reflog | ✅ **保留 90 天** |
