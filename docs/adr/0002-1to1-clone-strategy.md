# 0002 · 复刻策略: 1:1 还原云笔 230+ 端点

## 状态
已采纳 · 2026-06-07

## 背景
云笔 AI 是用户明确要求复刻的对标产品。存在三种复刻深度:
- **深度 A**: 只复刻核心功能 (项目/章节/续写)
- **深度 B**: 复刻大部分功能 (含世界设定)
- **深度 C**: 1:1 还原 (含 17 World Tab + 230+ 端点 + 12 厂商)

## 决策
**主控采用深度 C**: 1:1 还原云笔 230+ API 端点 + 17 World Tab 模块 + 12 AI 厂商注册表。

## 备选

### 备选 A: 仅核心功能
- ✅ 2-3 周即可上线
- ❌ 失去云笔的真正差异化 (世界设定系统)
- ❌ 用户明确说"主控 + 复刻", 不能砍

### 备选 B: 大部分功能
- ✅ 工作量适中 (3-4 个月)
- ❌ 边界模糊, 哪些做哪些不做
- ❌ 后续用户问"为什么 X 没做", 难以回答

### 备选 C (已采纳): 1:1 还原
- ✅ 边界清晰: 全部做
- ✅ 可以直接对标云笔, 行为一致
- ✅ knowlage 知识库已经是完整逆向, 1:1 反而省事
- ❌ 工作量大 (6-8 人月)

## 理由
1. knowlage/ 知识库已经完整扫描 87 个 wiki 页 + 19 个 raw 文件
2. 已有完整的真实 API 端点清单 (230+) 与 JSON 响应示例
3. 已有 11 条冲突裁决 (C01-C11), 1:1 的边界没有歧义
4. 用户期望"全栈项目, 好好管理", 不是 MVP

## 影响
- Sprint 0 工作量: 6-8 人月, 4-6 周
- 主控不砍需求, 全部按 knowlage 真实数据实现
- 子项目必须严格按 `contracts/openapi/*.yaml` 实现, 不允许私自简化
- 11 条冲突以 2026-06-03 新研究为准 (C01-C11)

## 后续
- 任何对云笔的"功能简化"或"业务调整", 必须开 ADR
- 主控在每周复盘时检查: 是否有子项目私加/私减功能
- 后续如果要超越云笔, 新建 ADR (例如 0003 改进蒸馏为 3 阶段)
