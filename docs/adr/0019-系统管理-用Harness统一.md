## 决策

**采用 Harness 统一管理方案 · 暂缓实施**

### 核心铁律(1 句话)

> **Harness 是 85% 的基础设施(现成,别造轮子)**
> **主控写 10% 的 glue code(喂配置给 Harness)**
> **主控亲自做 5% 的决策(Harness 干不了)**
>
> **地基用现成的,墙纸自己选。**

### 3 大块分工(决策定档)

| 块 | 谁干 | 主控工作量 | 占比 |
|---|------|----------|------|
| 🟢 Harness 直接管 | 9 脚本 + 8 Agent | 0 | 85% |
| 🟡 加点"调料" | 主控写 ~100 行 glue code | 1.5 小时(一次性) | 10% |
| 🔴 主控亲自干 | 决策/沟通/思考 | 每天 ~1 小时 | 5% |

## 备选

### 备选 A · 另起炉灶(教练之前差点做)
- ❌ 与 Harness 哲学严重偏离
- ❌ 主控记忆负担 = 4 标签 + 5 状态机 + 6 步
- ❌ 500+ 行主控自写代码
- ❌ 升级风险高

### 备选 B · 完全不用 Harness
- ❌ 主控每天翻 76 个文档
- ❌ 工作量 2-3 小时/天
- ❌ 准确性 70%(会漏)
- ❌ 子 agent 协调成本高

### 备选 C (已采纳) · Harness 统一管理
- ✅ 85% 复用现成机制
- ✅ 主控 1.5 小时一次性投入
- ✅ 0 心智负担(全自动化)
- ✅ 跟随 Harness 升级
