🧰 4 件套 = 子项目的"开工通知"

4 个子项目 × 4 件套 = 16 个文件。每个子项目开工前必须有它,缺一个就开不了工。

📖 故事 1:你买了 4 盒乐高

你想拼 4 辆小车(后端车、前端车、AI 车、网管车)。

你买了 4 盒乐高,每盒子上贴着 4 张纸条:

📋 第 1 张:你是谁 · CLAUDE.md
告诉孩子"这辆车叫啥,长啥样,谁能开,谁不能开"
📝 第 2 张:拼装步骤 · feature_list.json
告诉孩子"先拼轮子,再拼车身,最后拼方向盘"
✅ 第 3 张:今天拼到哪 · progress.txt
告诉孩子"昨天拼了 5 块,今天接着拼第 6 块"
🔌 第 4 张:电源开关 · init.sh
告诉孩子"按这个按钮,灯泡就亮了,车就能跑"

😱 没这 4 张纸条会怎样?
孩子(AI)打开盒子,看着 500 块零件,完全不知道从哪开始。
于是它瞎拼,拼出一辆" 4 个轮子朝天的车",然后跟你说"我干完了" 🤯

📖 故事 2:4 个新员工入职

公司来了 4 个新员工,HR(主控 = 你)给每人发 4 张纸:

🖥️
老后
后端程序员 · 写 API · 管数据库
🎨
小前
前端设计师 · 画页面 · 接 API
🧙
阿 AI
AI 调度员 · 召唤 12 法师
🌐
小运
网管 · Docker · 数据库 · 服务器

HR 说: "这 4 张纸,缺一张不能开工。"

  • 📋 岗位说明书(CLAUDE.md)— 知道自己干什么
  • 📝 任务清单(feature_list.json)— 知道今天做什么
  • ✅ 工作日志(progress.txt)— 知道做到哪了
  • 🔌 工卡(init.sh)— 进门刷一下,电脑开了

📖 故事 3:4 个人一起组装赛车

4 个人要一起组装一辆赛车( = 云笔 AI 小说助手)。

主控 = 车队经理,只查"小本子"(progress.txt),不亲自拧螺丝。

每个人的小本子长这样:

backend/progress.txt
================================
Day 1: 装好数据库 (PostgreSQL)
Day 2: 写完登录 API (POST /api/auth/login)
Day 3: 写完项目 API (GET /api/projects)
Day 4: 联调 - 前端调用登录,通了 ✅
Day 5: 写章节 API,做到一半...

👀 经理每天看一眼小本子:
· "哦,老后今天做到第 3 步了,不错"
· "小前还在第 1 步,催一下"
· "小运已经装好数据库,可以去联调了"

📖 故事 4:为啥是 4 件套,不是 3 件或 5 件?

1 件
❌ 啥都不知道
→ 瞎干
2 件
❌ 知道做啥
但不会启动
→ 干瞪眼
3 件
❌ 能干活
但不记日志
→ 出错找不到原因
4 件
✅ 刚好
身份 + 目标 + 进度 + 启动
5 件
❌ 多一张
"团队合影"
→ 没用

🚀 故事 5:施工队的"四级火箭"

1 CLAUDE.md · 身份
"我是谁?我干什么?我不准干什么?"
2 feature_list.json · 目标
"我要完成哪些任务?按什么顺序?谁依赖谁?"
3 progress.txt · 进度
"今天做到第几步了?哪些做完了?哪些卡住了?"
4 init.sh · 执行
"一行命令,把项目从 0 跑到能看"

📂 4 件套文件长什么样?

以 backend/ 为例:

backend/CLAUDE.md ← 岗位说明书 ───────────────────────────────── # 后端 (Backend) ## 你是谁 NestJS 后端服务,负责 230+ 个 API 端点。 ## 你的命令书 必须严格遵守 ../contracts/openapi/ 下的所有 YAML。 不准改字段名,不准删端点,改完要通知主控。 ## 你的禁区 ❌ 不准改 contracts/ (那是主控的) ❌ 不准自己设计 API (主控已设计好) ✅ 你只负责: 写实现 + 跑测试 + 写日志
backend/feature_list.json ← 任务清单 ───────────────────────────────── [ { "id": "B-01", "title": "搭建 NestJS 骨架", "passes": true }, { "id": "B-02", "title": "对接 PostgreSQL", "passes": true }, { "id": "B-03", "title": "实现登录 API", "passes": false }, { "id": "B-04", "title": "实现项目 API", "passes": false }, { "id": "B-05", "title": "联调 - 前端登录页", "passes": false } ]
backend/progress.txt ← 工作日志 ───────────────────────────────── 2026-06-07 Day 1 装好 NestJS 骨架,跑通 hello world 2026-06-08 Day 2 对接 PostgreSQL,写完 user 表 migration 2026-06-09 Day 3 实现 POST /api/auth/login,待前端联调
backend/init.sh ← 一键启动 ───────────────────────────────── #!/bin/bash docker compose up -d postgres pnpm install pnpm run db:migrate pnpm run start:dev echo "✅ 后端起在 http://localhost:3000"

🎯 一句话总结

4 个子项目 × 4 件套 = 16 个文件
16 个文件全到位,4 个施工队就能同时开工。
缺 1 个文件,就有 1 个队不知道干啥;
缺 4 个文件,4 个队全傻眼。

教练建议:16 个文件一次写完,写完一起 git commit,
4 个队就能"同时启动" 🚀
