🔑 关键发现

Harness 的 Agent 设计是 "只读为主,极少能改"。 这是为了 防止 AI 误改代码(只读是安全网)。 需要改动时,主控派人去做,或主控自己 Edit。

🔍 第 4 节

3 个关键发现(从源码读出的真相)

🔍 发现 1 · check-freshness 只管 CLAUDE.md

第 14 行注释明确写:Detects whether CLAUDE.md is stale。 不扫其他 76 个文档。所以"文档自动管理"这件事 Harness 没现成覆盖。

🔍 发现 2 · doc-gardener 能扫所有 docs/

第 27 行: Glob for all .md under docs/。 第 30 行: 用 Grep 验证每个代码引用 vs live source。 这就是我们要扩展的工具 — 它天然能扫全文档。

🔍 发现 3 · Harness 字段校验"宽松模式"

validate-config.mjs 只检查必填字段是否存在 + 已知字段格式, 不检查"未知字段"。所以加 document_registry 字段绝对安全,不会报错。

🎯 第 5 节

所有文档都要 Harness 管吗?不是,分 3 档

档数量怎么管现状用 Harness 哪个
🟢 Harness 原生管 1 check-freshness.mjs 自动扫 CLAUDE.md check-freshness
🟡 扩展可管 ~76 调 doc-gardener + wrapper 喂分类 docs/adr + discussions + sprints + briefs + contracts/ doc-gardener
⚪ 不需管 ~25 改即覆盖 README / HTML 故事 / 快照型文档 无

🎯 关键判断标准:"这个文档状态会变吗?"

会变 → 需要 Harness 管(stateful)
只追加不删 → 半自动(append-only)
改时升版本 → 自动(versioned)
改即覆盖无所谓 → 不用管(snapshot)

💡 实操建议

1. 第一波 · 用 doc-gardener 扫 docs/ 下所有 .md(76 个,全搞定)
2. 第二波 · 给 harness.config.json 加 document_registry 字段(告诉 doc-gardener 按 4 类分组)
3. 第三波 · 写 wrapper scan-docs.mjs 调 doc-gardener + 分类逻辑
