🚀 子 Agent 实施方案

主控如何调度多个子项目 Agent · 每个子 Agent 用 /harness-l3-v4 管理

⚡ 7 步实施 ⚠️ 5 个坑 📅 4 天启动计划

🏗️ 推荐架构 · 星型结构

核心思想: 主控 Agent 当"指挥塔",派任务给 N 个子 Agent,通过 contracts/ 共享对话。

🎩 主控 Agent (orchestrator)
↓ 派任务 + 给契约 ↓
🎨 frontend
Vue 3
⚙️ backend
NestJS
🧙 ai-orches.
Python
🗺️ knowledge
pgvector
🔧 infra
Docker
📜 共享 contracts/ (所有 agent 只读)

3 个关键约定:

  • 🎩 主控 Agent 永不下场写代码,只发图纸 + 看进度
  • 📜 所有子 Agent 只读 contracts/,不允许私自修改
  • 🔒 每个子 Agent 在独立 worktree,互不干扰

🚦 7 步实施流程

1

隔离工作目录 · git worktree

避免多个 agent 互改对方代码:

# 方法 A: 手动创建 worktree
cd master/
git worktree add ../wt-backend  backend-dev
git worktree add ../wt-frontend frontend-dev
git worktree add ../wt-ai       ai-dev

# 方法 B: 用 Agent 工具自动隔离 (推荐)
Agent({
  isolation: "worktree",
  subagent_type: "general-purpose",
  ...
})
2

每个子项目放"4 件套"

子 agent 一开工就要看到这些:

📋
1. 你是谁
CLAUDE.md
边界、职责、不允许做什么
📝
2. 任务清单
feature_list.json
从主控 37 任务里抽的子集
✅
3. 进度日志
progress.txt
每完一步追加一行
🔌
4. l3-v4 配置
harness.config.json
5 阶段研究/规划/构建/复盘/调试

⚠️ 没 4 件套就别派任务,否则子 agent 会瞎拼车!

3

派任务时给"3 个锚点"

每个子 agent 启动时,主控必须给:

🎯 任务 ID
"你做 S0-18 auth 模块"
📜 契约路径
"看 contracts/openapi/auth.yaml"
✅ 验收标准
"curl 登录返回 token"
4

用 /harness-l3-v4 包装每个子 Agent

每个子 agent 内部走 5 阶段:

# backend/harness.config.json
{
  "harness": {
    "version": "l3-v4",
    "phases": [
      { "id": "research", "inputs": ["../master/contracts/openapi/auth.yaml"] },
      { "id": "plan",     "outputs": ["docs/adr-auth.md"] },
      { "id": "build",    "outputs": ["src/modules/auth/"] },
      { "id": "review",   "scripts": ["pnpm test:auth"] },
      { "id": "debug",    "description": "修复 review 阶段发现的问题" }
    ]
  }
}
5

并行 vs 串行(看依赖)

✅ 能并行(同时跑)

  • 后端 auth 模块
  • 前端登录页面
  • 17 个 World Tab 契约编写
  • infra Docker 编排

→ 都不依赖对方运行

❌ 必须串行(排队)

  • 前端登录 ← 等后端 auth 跑起来
  • AI SSE ← 等前端编辑器写完
  • 蒸馏 ← 等 BullMQ + Redis
  • E2E 测试 ← 等所有人完工

→ 看 feature_list.json 的 depends 字段

6

主控当"裁判" · 每天 30 分钟

主控不下场写代码,只做 3 件事:

👀
看进度
读各 progress.txt,谁卡住?
🔍
查违规
跑 contract-lint,谁改契约?
⚖️
解冲突
前后端吵架时仲裁
7

完工交接协议

子 agent 完成任务时,必须:

  • ✅ 更新自己的 progress.txt
  • ✅ 在 feature_list.json 把 passes: false 改成 true
  • ✅ 跑通验收命令,贴输出
  • ✅ 写一行总结发回主控

🎬 具体启动姿势(代码示范)

Step 1 · 派 backend agent

Agent({
  subagent_type: "general-purpose",
  name: "backend-agent",
  isolation: "worktree",
  run_in_background: true,
  prompt: `
    你是 backend 子项目 agent。

    1. 必读: master/contracts/openapi/auth.yaml
    2. 任务: 完成 S0-18 auth 模块 (8 端点 + JWT + 心跳)
    3. 流程: 用 /harness-l3-v4 走 5 阶段
    4. 产出: backend/src/modules/auth/
    5. 验收: curl http://localhost:3000/api/auth/login
             返回 { success: true, data: { token, user } }
    6. 完工后: 更新 backend/progress.txt
              在 feature_list.json 把 S0-18 标 passes: true
  `
})

Step 2 · 同时派 frontend agent(并行)

Agent({
  name: "frontend-agent",
  isolation: "worktree",
  run_in_background: true,
  prompt: "做 S0-22 Vue 3 骨架, 不依赖后端先跑起来"
})

Step 3 · 主控等通知 → 派下一批

用 TaskOutput 看子 agent 的输出,根据进度派后续任务。

⚠️ 5 个坑 · 过来人血泪经验

❌ 坑✅ 怎么避
子 agent 互改对方代码必须用 isolation: "worktree" 隔离
子 agent 偷偷改契约主控加 contract-lint,子 agent 只读 contracts/
进度看不到子 agent 每完一步 立即写 progress.txt
同时 10 个 agent 跑爆 token一次最多 3-5 个并发
子 agent "自由发挥"CLAUDE.md 里 写死边界,列清楚不能做啥

📅 4 天启动计划

Day 1 · 主控补齐缺的图纸
  • 写 S0-09 chapter.yaml(11 端点)
  • 写 S0-10 outline.yaml(22 端点)
  • 写 S0-14 routing-rules.yaml(AI 路由规则)
  • 给每个子项目写 CLAUDE.md(4 件套之一)
Day 2 · 派 1 个 agent 试水
  • 启动 infra-agent
  • 任务: S0-04 init.sh + S0-15 docker-compose.yml
  • 验收: ./init.sh dev 启动 PG+Redis+MinIO 健康检查通过
  • 主控复盘: 这套调度模式行不行?有没有坑?
Day 3 · 派 3 个 agent 并行
  • backend-agent → 做 S0-16(NestJS 骨架) + S0-17(Prisma schema)
  • frontend-agent → 做 S0-22(Vue 3 骨架)
  • ai-agent → 做 S0-30 准备(读 DeepSeek 文档)
  • 主控盯进度,30 分钟看一次 progress.txt
Day 4-7 · 主链冲刺
  • backend: S0-18(auth)→ S0-19(project)→ S0-20(chapter)
  • frontend: S0-23(登录)→ S0-24(列表)→ S0-25(三栏)
  • ai: S0-29(SSE)→ S0-30(DeepSeek)
  • tests: S0-31(E2E 冒烟跑通)
  • 验收: 注册 → 登录 → 写 100 字 → AI 续写 → 采纳
