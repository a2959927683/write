小孩版 · Git 护栏人工检查

我们给工地装了栏杆, 现在要亲眼看它有没有立住。

Git 护栏就像游乐场门口的检查员: 谁能进去、能走哪条路、不能碰哪扇门, 都要先说清楚。 我已经把本地检查员装好了, 你要人工看的, 主要是 Gitee 那边有没有也开始站岗。

这个系统像什么?
agent 想提交代码 → 本地门卫先检查 → Gitee 远程再检查 → 通过了才能合并 OK

你要检查的 6 件事

看到“预期结果”就算正常。

1
Gitee

Gitee 有没有看到流水线?

像看学校门口有没有保安。推送分支后, 去 Gitee 看有没有出现叫 git-guard 的检查。

预期结果能看到流水线运行, 两个检查都通过: Contract lint 和 Hook syntax check。
2
最重要

master-codex 有没有被保护?

像把主城门上锁。不能让任何 agent 直接往主分支扔东西。

预期结果Gitee 设置里: 禁止直接 push, 必须走 PR/MR, 最好要求流水线通过才能合并。
3
本地

本地门卫有没有打开?

运行一条命令, 看 Git 是不是知道要去 `.githooks` 找门卫。

git config --get core.hooksPath
预期结果输出 `.githooks`。
4
契约

契约检查会不会通过?

像检查施工图纸有没有破洞。现在有些图纸还没画完, 所以只提醒, 不拦住。

python scripts/contract-lint.py
预期结果最后显示 `contract-lint passed`, 只看到 4 个已知 warning。
5
文档

工作流文档能不能看懂?

打开 `docs/git-workflow.md`, 你应该能知道 agent 怎么开分支、怎么提交、谁能改 contracts。

预期结果你能按文档说出: 一任务一分支、提交要带 `[S0-XX]`、子 agent 不碰 contracts。
6
边界

每个 agent 有没有自己的围栏?

打开 `backend/CLAUDE.md`、`frontend/CLAUDE.md` 等, 看它们有没有写清楚“我只能改哪里”。

预期结果backend 只能改 backend, frontend 只能改 frontend, 谁都不能私自改 contracts。

你不用检查什么

这一步不是验产品, 是验栏杆。

现在要看的

  • Gitee 有没有跑检查。
  • 主分支有没有被保护。
  • 本地 hook 有没有启用。
  • 文档是不是能指导 agent。

现在不要看的

  • 不要看登录能不能用。
  • 不要看前端页面漂不漂亮。
  • 不要看 AI 续写能不能跑。
  • 不要因为业务没开始就觉得失败。

一句话结论

如果 Gitee 流水线能跑、`master-codex` 被保护、本地输出 `.githooks`、contract lint 通过, 那 Git 护栏就算装好了。下一步才轮到 brief 机制和 infra-agent 试点。
